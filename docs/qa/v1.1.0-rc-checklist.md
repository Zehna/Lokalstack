# v1.1.0 Release Candidate — Testing Checklist

Manual QA checklist for the `localstack-control-center-1.1.0-rc` artifacts
before the v1.1.0 release decision. Use **only disposable synthetic data**:
no real credentials, no real project paths with sensitive names, no real
support bundles from the tester's own machine state that contain private
data. Back up user-owned `%LOCALAPPDATA%\localstack-control-center` state
before any live installation test on a machine with existing data. Never
modify or terminate unrelated processes during testing.

## 1. Provenance

- [ ] RC built from source commit `86452bf66e4a5f505be846f28fedd2a98036d075`
      (main after PR #7 merge) or a direct descendant recorded here: ________
- [ ] GitHub Actions run for the build recorded here: ________ (release
      workflow dispatched from the RC branch after it merges to main)
- [ ] `Quality gates (windows-latest)` green on that commit
- [ ] Artifact set downloaded from the recorded run only (never from an
      older run, branch, or local ad-hoc build)

## 2. Artifact inventory & integrity

- [ ] Artifact name is exactly `localstack-control-center-1.1.0-rc`
- [ ] Contains exactly four files (collection guard enforces this):
      `LocalStack Control Center_1.1.0_x64_en-US.exe` (NSIS),
      `LocalStack Control Center_1.1.0_x64_en-US.msi` (MSI),
      `localstack-control-center-standalone.exe`, `SHA256SUMS.txt`
- [ ] No stale/duplicate/other-version files (workflow fails the run if any)
- [ ] `sha256sum -c SHA256SUMS.txt` passes independently on the tester's
      machine (not only inside CI)

## 3. Windows 10/11 x64 compatibility

- [ ] NSIS install launches on Windows 11 x64
- [ ] NSIS install launches on Windows 10 x64 (or 21H2+ equivalent)
- [ ] MSI install completes (per-machine policy, UAC prompt; `/passive`
      works, `/qn` is documented as non-functional)
- [ ] No administrator requirement for the NSIS per-user install
- [ ] SmartScreen unsigned-binary warning appears and *More info → Run
      anyway* proceeds

## 4. Production launch (no dev tooling)

- [ ] App launches from Start Menu with no source tree, Node.js, or Vite
      dev server present
- [ ] Version shown in the UI/Settings is 1.1.0 (Tauri-injected, not
      hardcoded)
- [ ] Tray icon behaves: show/hide, close-to-tray setting respected
- [ ] Single-instance enforcement works (second launch focuses existing)

## 5. Upgrade from v1.0.1

- [ ] Back up `%LOCALAPPDATA%\localstack-control-center` first
- [ ] Installing 1.1.0 over an existing v1.0.1 installation succeeds
- [ ] Settings, workspace/project state, and `localstack.log` survive the
      upgrade (Phase 11C lazy-migration rule: no destructive migration)
- [ ] Diagnostics directories (`diagnostics/`, incident index) are created
      lazily on first use, not pre-populated with invented data
- [ ] Downgrade not tested unless explicitly planned (document if skipped)

## 6. Settings & tray regression

- [ ] Settings page loads, edits persist across restart
- [ ] Tray toggle, close-to-tray, and autostart behavior unchanged
- [ ] No regression in ports/dashboard/workspaces views

## 7. Diagnostics page & deep health

- [ ] Diagnostics page reachable from navigation; four tabs render
- [ ] Run Deep Diagnostics completes; statuses have text (never color-only)
- [ ] `Skipped`/`Unavailable` states render as informational, not errors
- [ ] Overview shows app version 1.1.0, storage usage, bundle count
- [ ] Non-elevated session: all checks runnable without UAC

## 8. DPAPI-encrypted internal bundles

- [ ] Trigger one synthetic severe incident; a support bundle captures in
      the background (no UI freeze, no dialog opened by the capture worker)
- [ ] `.lsdiag` file under `diagnostics/bundles/` is DPAPI-encrypted:
      opening it in an editor shows no plaintext canary strings
- [ ] Bundle detail view decrypts for the same Windows user
- [ ] Bundle from another user account / profile is NOT decryptable
      (current-user scope verified)

## 9. Export profiles

- [ ] Safe Share export: synthetic username/hostname/SID/MachineGuid/MAC/
      local IP/full paths are generalized or absent
- [ ] Developer Detail export: full paths/project names retained; unique
      machine identifiers absent; warning shown
- [ ] Full Forensics export: per-export confirmation modal required every
      time; identity fields retained
- [ ] ALL profiles: synthetic secrets (token, password, api_key,
      `Authorization: Bearer`, Cookie, private-key-shaped text) are absent
      from every section, summary, filename, and the GitHub preview
- [ ] Exported ZIP opens with a standard ZIP tool; SHA256SUMS-independent
      content matches the detail view

## 10. Secret-redaction canaries (synthetic)

- [ ] Seed managed-service output and incident summaries with synthetic
      canaries (`token=SYN…`, `password=SYN…`, `api_key=SYN…`,
      `Authorization: Bearer SYN…`, `Cookie: SYN…`, fake PEM block) before
      capture
- [ ] Canaries absent from: incident index, bundle metadata, encrypted
      payload after decrypt, all three export profiles, Copy Diagnostic
      Summary, GitHub issue title/body
- [ ] Delete all synthetic-data bundles after the test

## 11. Notifications & crash recovery

- [ ] Foreground capture → in-app banner only (no Windows toast)
- [ ] Background/minimized capture → Windows native notification; anti-spam
      cooldown prevents toast spam under repeated synthetic triggers
- [ ] Focus-query failure path degrades to in-app banner (if testable)
- [ ] Simulate crash (synthetic panic path) → next startup offers recovery;
      one in-app banner after UI ready; recovery does not block startup
- [ ] Max-3-attempt recovery limit respected; `failed/` escalation on
      persistent failure

## 12. Uninstall & state

- [ ] NSIS uninstall removes app files; user state under
      `%LOCALAPPDATA%\localstack-control-center` is retained (documented)
- [ ] No orphaned services, scheduled tasks, firewall rules, or unrelated
      registry changes after uninstall
- [ ] Reinstall restores prior settings (state preservation confirmed)

## 13. Test-data hygiene

- [ ] All synthetic bundles/incidents deleted after testing
- [ ] Backed-up user state restored if a live upgrade was performed
- [ ] No real credentials ever entered at any step
